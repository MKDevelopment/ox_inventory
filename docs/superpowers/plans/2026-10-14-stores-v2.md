# Stores v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shopkeeper peds with ox_target/tgiann-target, one store UI with a live cart for MyStory stores and default ox shops, payments from carried cash and tgg-banking cards, and food that always carries expiry data.

**Architecture:** A server `Payments` module lists and charges payment options from what the player carries (cash through the wallet-aware inventory, cards through tgg-banking). MyStory stores and a new ox-shop store adapter both use it and return the same `StoreData` to the existing React `StoreApp`. A small client target bridge registers ped options with tgiann-target or ox_target. Food defaults are applied when the item list is built.

**Tech Stack:** Lua 5.4 (CfxLua), ox_lib, oxmysql, tgg-banking and tgiann-target/ox_target exports, React + TypeScript, Python + lupa mock tests.

**Spec:** `docs/superpowers/specs/2026-10-14-stores-v2-design.md`

## Global Constraints

- All code in English; user-facing text only in `locales/en.json` and `locales/pl.json`.
- Card metadata keys come from `config.cardFields` in `data/stores.lua`: `id = { 'cardId', 'id' }`, `number = { 'cardNumber' }`, `name = { 'displayName' }`.
- Payments config: `payments = { cash = true, personal = true, business = true }`; shared cards (`debitcard_shared`) are never offered.
- Every tgg-banking call goes through `pcall` and is skipped when `GetResourceState('tgg-banking') ~= 'started'`.
- Spoilage defaults (minutes): tiers `restaurant = 2880, fastfood = 1440, snack = 20160, restaurantdrink = 1440, hotdrink = 1440, junkdrink = 43200`; categories `food = 4320, drinks = 43200, ingredients = 10080`.
- `data/stores.lua` `target = 'auto'`; `defaultPed = { model = 'mp_m_shopkeep_01', scenario = 'WORLD_HUMAN_STAND_IMPATIENT' }`.

## Review Focus

1. A card listed when the store opened but dropped or given away before paying: the charge is refused and nothing is taken. Test `charge_card_gone`.
2. A business card held by someone outside the company: shown disabled (`no_access`), and a forged checkout with its id is refused. Test `business_no_access`.
3. Paying more than the selected option holds while the cart total is shown as affordable for another option: refused with `store_cannot_afford`, stock untouched. Test `charge_insufficient`.
4. An ox shop product locked by licence or grade sent in a forged cart: refused, nothing charged. Test `shop_locked_product`.
5. A food item that already has `degrade` in `data/items.lua`: keeps its own value. Test `food_degrade_override`.
