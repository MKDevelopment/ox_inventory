# Wallet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `wallet` item holding cards and documents plus a cash amount that counts as the player's ESX cash, with configurable theft protection.

**Architecture:** A dependency-free helper `modules/wallet/cash.lua` reads and spends `metadata.cash` of wallets in a player inventory. `modules/inventory/server.lua` calls it from `GetItemCount`, `GetItem` (count mode), `Search` (count mode), `GetAccountItemCounts` and `RemoveItem` for `money` on player inventories. The checks live inside those functions because exports are bound to the original function references and cannot be wrapped from outside. `modules/wallet/server.lua` adds the deposit and withdraw callbacks and the `swapItems` hooks for drag-deposit and theft. The NUI shows a cash panel above an open wallet.

**Tech Stack:** Lua 5.4 (CfxLua), ox_lib callbacks, ox hooks, React + TypeScript NUI, Python + lupa mock tests in the scratchpad.

**Spec:** `docs/superpowers/specs/2026-10-14-wallet-design.md`

## Global Constraints

- All code, identifiers and comments in English; user-facing text only in `locales/en.json` and `locales/pl.json`.
- Only the `money` item is wallet-aware; `black_money` and every other item keep their current behaviour.
- Only wallets in the player's own main inventory slots count.
- `RemoveItem` with `slot` or `metadata` keeps the original behaviour.
- Amounts are integers: `math.floor(count + 0.5)`, the same rounding `RemoveItem` uses.
- Settings in `data/wallet.lua`: `slots = 10`, `steal = 'police'` (`false` | `'police'` | `true`), `searchable = { 'debitcard_personal', 'debitcard_shared', 'debitcard_business' }`.

## Review Focus

1. Paying more than the pocket holds but less than pocket + wallets: everything is charged, nothing is left negative. Covered by test `pay_pocket_and_wallet`.
2. Paying more than pocket + wallets: returns `false, 'not_enough_items'` and changes nothing. Covered by test `pay_not_enough`.
3. ESX `SetItem(inv, 'money', lower)` when the pocket alone is below the target difference: the wallet gets lowered and the total matches the target. Covered by test `setitem_lowers_wallet`.
4. A withdraw request for someone else's slot, a non-wallet slot, a negative or fractional amount, or more than the wallet holds: rejected, nothing changes. Covered by test `withdraw_validation`.
5. A thief dragging a wallet out of a victim's inventory with `steal = 'police'`: blocked for civilians, allowed for police jobs. Covered by test `steal_rules`.

### Task 1: Cash helper and inventory accounting

**Files:**
- Create: `modules/wallet/cash.lua`
- Modify: `modules/inventory/server.lua` (`GetAccountItemCounts`, `GetItem`, `Search`, `RemoveItem`, `GetItemCount`)
- Test: `scratchpad/test_wallet.py`

**Interfaces:**
- Produces, in `modules/wallet/cash.lua` (returns a table `WalletCash`, no requires):
  - `WalletCash.get(inv: OxInventory) -> integer`: sum of `metadata.cash` of `wallet` items in `inv.items`; 0 when `inv.player` is nil.
  - `WalletCash.take(inv: OxInventory, amount: integer) -> table<integer, integer>`: lowers wallet `metadata.cash` in ascending slot order until `amount` is covered and returns `{ [slot] = newCash }` for each changed wallet. The caller must have checked that the wallets hold enough.
- Inventory changes, all only when `inv.player` and the item is `money`:
  - `GetItemCount(inv, 'money')` and `GetItem(inv, 'money', nil, true)` add `WalletCash.get(inv)` when `metadata` is nil.
  - `Search(inv, 'count', 'money')` adds it to the `money` count.
  - `GetAccountItemCounts(inv)` adds it to `accounts.money`.
  - `RemoveItem(inv, 'money', count)` with no `slot` and no `metadata`: if the pocket holds less than `count`, the wallets cover the rest (`ignoreTotal` caps the amount at pocket + wallets). The pocket part goes through the existing loop, then each changed wallet slot gets `Inventory.SetMetadata(inv, slot, { ...metadata, cash = newCash })`.

### Task 2: Wallet item, settings, deposit and withdraw, theft hook

**Files:**
- Create: `data/wallet.lua`, `modules/wallet/server.lua`
- Modify: `data/items.lua` (add `wallet` to the documents section), `modules/items/containers.lua`, `server.lua` (require `modules.wallet.server`), `data/metadata.lua` (display key `cash`), `locales/en.json`, `locales/pl.json`
- Test: `scratchpad/test_wallet.py`

**Interfaces:**
- Consumes: `WalletCash.get`, the wallet-aware `RemoveItem`.
- Produces:
  - `data/wallet.lua` returns `{ slots = 10, maxWeight = 500, steal = 'police', searchable = {...} }`.
  - Item `wallet`: `label = 'Wallet'`, `weight = 100`, `stack = false`, `close = false`, `category = 'documents'`, `description` set.
  - Container: `setContainerProperties('wallet', { slots, maxWeight, whitelist })`, where the whitelist lists every `ItemList` entry with `category == 'documents'` except `wallet`.
  - Callback `ox_inventory:walletDeposit(source, slot: integer, amount: integer) -> boolean, string?`: moves `amount` loose `money` into the wallet in `slot`.
  - Callback `ox_inventory:walletWithdraw(source, slot: integer, amount: integer) -> boolean, string?`: lowers the wallet's cash and adds `amount` `money` to the pocket after `CanCarryItem`.
  - Both callbacks reject a slot that holds no `wallet` in the caller's own inventory, an amount that is not a positive integer, or an amount above the source (pocket for deposit, wallet for withdraw). They log through `lib.logger(inv.owner, 'wallet', ...)`.
  - `swapItems` hook: when a `money` stack is dropped onto a `wallet` slot in the same player inventory, it returns `false` and deposits the dragged count on the next tick.
  - `swapItems` hook with `itemFilter = { wallet = true }`: when `fromType == 'player'` and `fromInventory ~= source`, it allows the move only when `steal == true`, or when `steal == 'police'` and `server.hasGroup(Inventory(source), shared.police)`. Otherwise it notifies `wallet_cannot_steal` and returns `false`.
  - Locales: `wallet_cannot_steal`, `wallet_invalid_amount`, `wallet_not_enough`, `wallet_cannot_carry`, `meta_cash`, `ui_wallet_cash`, `ui_wallet_deposit`, `ui_wallet_withdraw`.

### Task 4: Cards in the wallet

**Files:**
- Modify: `modules/wallet/cash.lua` (rename the module role to wallet helpers: add `WalletCash.items(inv, name) -> table[]`), `modules/inventory/server.lua` (`GetItemCount`, `GetItem` count mode, `Search`, `GetSlotWithItem`, `GetSlotsWithItem`), `modules/wallet/server.lua` (callback `ox_inventory:walletTakeOut(source, containerSlot) -> integer?`), `client.lua` (NUI callback `walletUse`), `web/src/components/inventory/InventorySlot.tsx` and its context menu (use action for wallet container slots)
- Test: `scratchpad/test_wallet.py`

**Interfaces:**
- `WalletCash.items(inv, name)`: for a `searchable` name and a player inventory, returns copies of matching slot tables from every wallet container (`Inventory(metadata.container)` or `Inventory.Create` like `GetContainerFromSlot`), each with `wallet = walletSlot`; `{}` otherwise.
- Lookups append these after the pocket results; counts add their `count`.
- `ox_inventory:walletTakeOut(source, containerSlot)`: the caller's open container must be a wallet in their own inventory (`inv.containerSlot`); it moves the item to the first free pocket slot (`Inventory.GetEmptySlot`) via `Inventory.RemoveItem(container, name, count, nil, containerSlot)` plus `Inventory.AddItem(inv, name, count, metadata, freeSlot)` and returns the pocket slot; `nil` with a notify when the pocket is full.
- The client `walletUse` callback awaits it and calls `useSlot(pocketSlot)`.
